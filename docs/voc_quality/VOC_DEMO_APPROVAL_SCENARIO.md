# VOC 품질진단 최종 녹화 시연 기준

## 문서 목적

기능 구현이 완료된 뒤 수행할 최종 화면 시연과 녹화의 고정 기준이다. 이후 추가 기능이 생기면 이 문서를 기준으로 시연 구간을 확장한다.

최종 증적 흐름:

`Dashboard → Agent 전체 시작 → 품질기준 → TC-01 Pipeline → 독립성 보완 → 수행 이력 → 타당성 AI_PASS → QA_REVIEWED → BUSINESS_APPROVED`

## 녹화 원칙

- 마우스 포인터의 이동, 클릭, 입력, 팝업 전환과 스크롤이 모두 보여야 한다.
- 화면마다 설명 HUD를 짧게 표시하되 실제 데이터와 주요 판정 영역을 가리지 않는다.
- 입력이나 클릭이 없는 긴 정지 구간을 만들지 않는다.
- 단, 실시간 Agent Pipeline은 실행 상태가 핵심이므로 화면을 이동하지 않고 완료까지 그대로 녹화한다.
- 점수나 상태를 임의로 변경하지 않는다.
- 실제 평가가 Gate를 충족하지 못하면 승인 상태를 강제로 만들지 않는다.
- 시연용 보완 입력은 실제 운영 근거가 아니라 승인 흐름 검증용 자료임을 밝힌다.

## 1. Dashboard 요약

경로: `홈 > VOC 품질진단 > Dashboard`

약 15~20초 동안 다음 의미를 짧게 보여준다.

1. 실행 환경: 필수 파일과 환경 설정의 준비 상태
2. Agent 가동: 6개 Agent 프로세스의 현재 가동 수
3. 최신 Run 품질: PASS, 검토 필요, 실패와 오류 현황
4. 독립 Judge: 최신 Run의 독립 평가 상태
5. 미종결 결함: 기간 내 Open 결함과 High/Critical 건수
6. A2A 연결 상태: Agent 간 연결과 Trace 수집 상태
7. 기간 Run 판정 추이와 Agent 운영 상태

발표 문구:

> Dashboard는 실행 환경부터 Agent, 최근 품질 판정, 독립 평가와 결함까지 현재 VOC 품질 상태를 한 화면에서 요약합니다.

## 2. Agent 관리 전체 시작

경로: `홈 > VOC 품질진단 > Agent 관리`

1. Agent 상태 변경 체크박스를 선택한다.
2. `전체 시작`을 누른다.
3. Interpreter부터 Improver까지 6개 Agent의 시작 진행 로그를 보여준다.
4. 전체 Agent가 실행 중인지 확인한다.

`전체 재시작`이 아니라 시연의 시작 의미가 명확한 `전체 시작`을 사용한다. 이미 실행 중인 Agent는 유지되고 중지된 Agent만 시작되는 현재 정책을 설명한다.

## 3. 품질 평가 기준 빠른 순회

경로: `홈 > VOC 품질진단 > 품질 평가 기준`

전체 체류 시간은 약 25~35초를 목표로 한다.

각 탭에서 다음 동작만 빠르게 보여준다.

1. `내부 Pipeline 품질`
   - 탭 선택
   - 첫 평가항목을 선택해 `세부 배점 설정` 팝업 표시
   - 항목 배점, 세부 기준과 PASS 하한을 가리킨 뒤 팝업 닫기
2. `독립 LLM Judge`
   - 탭 선택
   - 첫 평가항목의 `세부 배점 설정` 팝업 표시
   - 독립성·근거성 평가 기준을 짧게 보여주고 닫기
3. `개선안 타당성`
   - 탭 선택
   - 첫 평가항목의 `세부 배점 설정` 팝업 표시
   - 실행 가능성·KPI·리스크 기준을 짧게 보여주고 닫기

Rubric 버전·기준명·Provider·저장 버튼 화면에 오래 머물지 않는다. 각 탭의 “기준을 사용자가 관리할 수 있다”는 의미만 전달하고 다음 단계로 이동한다.

## 4. TC-01 실시간 Agent Pipeline

경로: `홈 > VOC 품질진단 > 수동 TC 수행`

1. 읽기 전용 목록에서 `TC-01` 행을 클릭한다.
2. Case 질문과 판정 기준을 짧게 확인한다.
3. `Agent Pipeline 실행`을 누른다.
4. 실시간 Agent Pipeline 영역이 잘 보이는 위치로 이동한다.
5. 이후에는 스크롤, 메뉴 전환, 반복 HUD 변경 없이 화면을 그대로 유지한다.
6. Interpreter, Retriever, Summarizer, Evaluator, Critic, Improver가 순서대로 완료되는 모습을 끝까지 녹화한다.
7. Pipeline 완료 후 Run ID, Trace ID와 최종 개선안을 보여준다.

이 구간은 정적인 화면이 아니라 실시간 상태 변화 자체가 시연 내용이므로 마우스도 Pipeline 영역 옆에 정지한다.

## 5. 독립성 평가와 보완

1. 첫 Judge는 생성 모델과 같은 Provider 조건의 독립성 결과를 확인한다.
2. 점수가 높아도 독립성 C이면 `REVIEW_REQUIRED`가 되는 것을 보여준다.
3. 생성 모델과 다른 Gemini Judge를 선택한다.
4. 저장된 동일 Pipeline 결과를 재평가한다.
5. Provider, 모델, 점수, 독립성 A 또는 B와 유효 판정을 확인한다.

발표 문구:

> 품질 점수와 모델 독립성은 별도 기준입니다. 동일 Provider의 편향 가능성은 점수를 수정하지 않고 다른 Provider의 재평가로 보완합니다.

## 6. 최신 수행 이력 팝업

경로: `홈 > VOC 품질진단 > 수행 이력`

1. 방금 생성한 Run ID가 첫 행에 있는지 확인한다.
2. 해당 행을 클릭한다.
3. 실행 상세 팝업을 연다.
4. 다음 탭을 빠르게 순회한다.
   - Case 결과
   - 실행 정보
   - Case 증적
5. TC-01의 Pipeline, Trace, Rule, Judge 증적이 같은 Run에 연결된 것을 보여준다.
6. 팝업을 닫고 다음 단계로 이동한다.

VOC 수행 이력은 `Run 행 클릭 → 수행 이력 상세 팝업`으로 동작한다. 팝업을 닫은 뒤에는 `선택 Run 상세` 버튼으로 같은 Run을 다시 열 수 있다.

## 7. 개선안 타당성 보완 입력

경로: `홈 > VOC 품질진단 > 개선안 타당성 검증`

1. 방금 수행한 Run ID를 검색한다.
2. `TC-01`을 선택한다.
3. 독립 평가와 Run·Case·Trace 연결 상태를 확인한다.
4. 다음 여섯 항목을 직접 입력하는 장면을 보여준다.

| 항목 | 시연 입력 내용 |
|---|---|
| 담당·오너 | QA 책임자, 업무 승인자, 운영 지원 조직 |
| 일정·마일스톤 | 설계, QA, 단계 배포, 효과 검증 일정 |
| 정량 KPI | 오류율, 성공률, 응답시간, 상담 전환율 목표 |
| 우선순위 | P1 및 우선 개선 대상 |
| VOC·Trace 근거 | 방금 수행한 Run ID, Trace ID, TC-01과 Agent Trace |
| 리스크·회피방안 | 단계 배포, 롤백 조건, 개인정보 보호, 승인 조건 |

5. `보완 입력 저장`을 누르고 보완 입력 적용 상태를 확인한다.

## 8. 자동 타당성 평가와 AI_PASS

1. 자동 평가 Provider와 모델을 확인한다.
2. `선택 대상 자동 타당성 평가 실행`을 누른다.
3. 보완 입력, Pipeline, Trace와 독립 Judge 결과가 평가 입력에 포함되는 것을 보여준다.
4. 실제 결과가 `AI_PASS`인지 확인한다.
5. 즉시 보류 규칙이 없고 QA 검토 가능 상태인지 확인한다.

`AI_PASS`가 아니면 보완 권고를 보여주고 녹화를 중단한다. 점수나 상태는 임의 변경하지 않는다.

## 9. QA 검토

1. 검토자와 QA 검토 의견을 입력한다.
2. 독립성, 타당성 점수, 즉시 보류 규칙과 Run·Trace 증적을 확인했음을 기록한다.
3. 승인으로 `검토 결과 저장`을 누른다.
4. `QA_REVIEWED` 또는 `QA 검토 완료` 상태를 화면에 표시한다.

## 10. 업무 승인

1. QA 검토 완료 후 업무 승인 양식이 활성화되는 것을 보여준다.
2. 같은 시연자가 업무 승인자 역할로 적용 범위, KPI, 단계 배포와 롤백 기준을 검토한다.
3. 승인 의견을 입력하고 `검토 결과 저장`을 누른다.
4. `BUSINESS_APPROVED`와 `정식 승인 완료`를 확인한다.

한 사람이 두 역할을 수행하더라도 QA와 업무 승인은 역할·시각·의견이 분리된 감사 이력으로 저장한다.

## 11. 강한 종료 연출

승인 완료 화면을 2~3초 보여준 후 전체 화면 종료 오버레이를 표시한다.

- 큰 체크 아이콘과 `VOC 품질진단 시연 완료`
- `Pipeline → 독립 평가 → AI_PASS → QA 검토 → 업무 승인`
- 최종 상태 `BUSINESS_APPROVED`
- 파란색·초록색 그라데이션, 빛나는 테두리와 콘페티 효과
- 약 8초간 유지한 뒤 화면은 정식 승인 결과에 멈춘다.

발표 문구:

> 실제 VOC 근거에서 시작해 독립 평가와 타당성 검증, QA와 업무 승인을 모두 통과했습니다. VOC 품질진단 전체 시연을 마칩니다.

## 최종 녹화 전 완료 조건

- [ ] Dashboard 주요 카드와 차트가 정상 표시된다.
- [ ] Agent `전체 시작` 진행 로그와 최종 상태가 정상 표시된다.
- [ ] 평가기준 3개 탭의 세부 배점 팝업을 자동으로 열고 닫을 수 있다.
- [ ] TC-01 Pipeline이 성공하고 실시간 화면이 완료까지 유지된다.
- [ ] 독립성 C와 다른 Provider 재평가 A/B 흐름이 재현된다.
- [x] 최신 수행 이력 클릭 시 실행 상세 팝업이 열린다.
- [ ] TC-01 타당성 평가가 실제 `AI_PASS`를 만족한다.
- [ ] `QA_REVIEWED → BUSINESS_APPROVED` 순차 승인이 동작한다.
- [ ] 종료 오버레이와 콘페티 연출이 정상 표시된다.

## 자동화 명령 기준

최종 기능 완료 후 `.artifacts/demo/live_controller.js`의 전체 녹화 동작을 이 문서 순서로 갱신한다. 실행 명령은 방금 생성한 Run ID와 Trace ID를 후속 단계에 자동 전달해야 하며, 과거 Run을 고정값으로 사용하지 않는다.

현재 `approval_recording_demo`는 승인 구간 자동화 초안이다. 최종 녹화에서는 Dashboard부터 종료 연출까지 하나의 연속 동작으로 통합한다.
