# AI QA GitHub Pages Portfolio

20년+ QA·IT 실무 경험을 AI Agent QA, QA Automation, LLM Evaluation, Monitoring으로 확장해 보여주는 정적 포트폴리오입니다.

## 공개 페이지 구성

참고 포트폴리오의 실제 흐름인 `정체성 → 핵심 지표 → 일하는 방식 → 대표 프로젝트 → 역량 → 기여 역할 → 연락`을 유지하고, 공개 가능한 확인 자료가 있는 AI QA 내용으로 재구성했습니다.

1. Hero: `AI를 검증 가능한 품질로 바꿉니다.`
2. At a glance: `20+`, `2026`, `04`, `Test → Evaluate → Monitor → Improve`
3. Profile: 기존 QA 경험에서 AI Agent 품질관리로 확장되는 이야기
4. Framework: `Test → Evaluate → Monitor → Improve` 품질 루프
5. Selected work: 요청한 네 개 프로젝트
6. Toolkit: 교육·실습·프로젝트 자료에서 확인되는 기술과 도구
7. Contribution: AI Agent QA, QA Automation, RAG/Tool QA, Monitoring & PM
8. Contact: 공개 저장소와 연락처 링크를 배포 직전에 추가하는 영역

## 네 개 프로젝트 문구

- **AI Agent QA & Monitoring**: 기능 테스트, 품질평가, k6 성능 테스트, Prometheus·Grafana 관측성, Docker Compose·Streamlit·Jira 확장 흐름
- **VOC Multi-Agent QA / AWS 운영감사**: Multi-Agent Pipeline, 독립 LLM Judge, QA·업무 승인, Trace와 AWS S3 증적 보관
- **RAG Chatbot 품질평가**: 문서 업로드, 검색 기반 답변, 정확성·근거성·환각 여부·검색성능 평가, Judge Agent
- **Tool Calling Agent 품질진단**: Tool 선택, 인자 전달, 실행 결과, 오류처리와 Happy·Edge·Negative 테스트

## GitHub Pages 배포

이 폴더의 세 파일을 저장소 루트에 올리거나, 저장소의 Pages source로 지정하면 됩니다.

```text
index.html
styles.css
script.js
```

GitHub 저장소와 개인 연락처는 사용자가 공개를 결정한 뒤 `index.html`의 Contact 영역에 추가하세요. 현재 산출물에는 확인되지 않은 이메일·저장소 주소를 넣지 않았습니다.

## 공개 전 점검

- 실제 GitHub 저장소 URL과 연락처 추가
- 각 Notion 페이지의 공개 공유 권한 확인
- 개인별 프로젝트 역할과 기여 범위 확인 후 문구 보강
- 실제 경력 연도·기업·성과 수치 확인 후 Career 섹션 추가
- Notion 원문이 비공개라면 공개용 별도 문서로 대체

세부 근거와 의도적으로 제외한 정보는 `CONTENT_SOURCES.md`에 기록했습니다.
