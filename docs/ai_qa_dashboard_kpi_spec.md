- 상태: `APPROVED`
- 승인 시각: `2026-07-14`
- 진행 단계: `Task 1 - KPI·SLO·화면 범위 확정`
- 기준 시간대: `Asia/Seoul`
- 기본 조회 기간: 최근 7일
- 일 API 비용 예산: `50,000 KRW`

## 1. 정의 원칙

1. 화면의 모든 수치는 동일한 기간·환경·서비스·모델 필터를 적용한다.
2. 실제 계측값을 우선하며, 추정값은 반드시 `추정`으로 표시한다.
3. 데이터가 없으면 `0`이 아니라 `데이터 없음`으로 표시한다.
4. 프롬프트·응답·사용자 식별자 같은 원문은 Prometheus label에 저장하지 않는다.
5. 카드 수치와 상세 화면의 집계 공식은 하나의 집계 API를 공유한다.
6. 각 지표에 마지막 수집 시각과 데이터 신선도 상태를 함께 제공한다.

## 3. 상단 핵심 KPI

| ID | 지표 | 산식 | 단위 | 권장 상태 기준 | 주 데이터 원천 | 현재 상태 |
|---|---|---|---|---|---|---|
| Q-001 | 전체 품질점수 | 평가된 `accuracy`, `groundedness`, `helpfulness`, `safety` 점수의 평균 ÷ 5 × 100 | 점 | 정상 ≥ 90, 주의 80~89.9, 위험 < 80 | 평가 결과 DB | 일부 가능 |
| T-001 | 테스트 통과율 | PASS ÷ (PASS + FAIL + ERROR) × 100 | % | 정상 ≥ 95, 주의 85~94.9, 위험 < 85 | 테스트 실행 이력 | 가능 |
| P-001 | p95 전체 응답시간 | 선택 기간의 요청 소요시간 95백분위수 | 초 | 정상 ≤ 5, 주의 > 5~8, 위험 > 8 | Prometheus histogram | 가능 |
| P-002 | 서비스 오류율 | (HTTP 5xx + timeout) ÷ 전체 요청 × 100 | % | 정상 ≤ 1, 주의 > 1~2, 위험 > 2 | API 계측·Prometheus | 보완 필요 |
| S-001 | 안전성 위반 | 기간 내 High 또는 Critical 안전성 위반 건수 | 건 | 정상 0, 위험 ≥ 1 | 안전성 평가 이벤트 | 보완 필요 |
| C-001 | API 비용 | 공급자 usage × 호출 당시 단가의 합계 | 원 | 정상 < 40,000원, 주의 40,000~50,000원, 위험 > 50,000원 | LLM usage 이벤트·가격표 | 미구현 |

### KPI 해석 규칙

- Q-001은 현재 실제로 평가되는 네 지표만 사용한다. `관련성`, `신뢰성`을 별도 지표로 추가하려면 Task 2에서 정의와 저장 필드를 먼저 확정한다.
- T-001의 ERROR는 성공으로 간주하지 않으며 전체 시도 건수의 분모에 포함한다.
- P-002는 서비스 책임 범위를 명확히 하기 위해 5xx와 timeout을 기본 오류로 본다. 4xx는 별도 `클라이언트 오류율`로 제공한다.
- C-001은 문자 수 추정값을 공식 비용으로 사용하지 않는다. 공급자 응답의 실제 token usage가 없으면 `데이터 없음` 또는 `추정`으로 구분한다.

### 전체 운영 상태 우선순위

1. 안전성 High/Critical 위반이 1건 이상이면 전체 상태는 `위험`이다.
2. 하나 이상의 핵심 KPI가 위험이면 전체 상태는 `위험`이다.
3. 위험은 없지만 하나 이상의 핵심 KPI가 주의이면 전체 상태는 `주의`다.
4. 모든 핵심 KPI가 정상이고 데이터가 최신이면 전체 상태는 `정상`이다.
5. 필수 데이터가 없거나 신선도 기준을 충족하지 못하면 `판정 불가` 또는 `수집 지연`을 우선 표시한다.

전체 품질점수는 요약값이며 개별 안전성·오류·성능 상태를 덮어쓰지 않는다.

## 10. 사용자 결정 항목

1. 전체 품질점수는 MVP에서 현재 수집 가능한 네 지표를 동일 가중치로 사용한다. `승인`
2. 서비스 오류율은 5xx와 timeout만 포함하고 4xx는 별도 표시한다. `승인`
3. MVP는 JSONL 이벤트 로그와 일별 집계 CSV로 시작하고 저장소 계층을 분리한다. SQLite는 데이터 증가 시 별도 승인 후 확장한다. `변경 승인`
4. 테스트 통과율 목표는 고급 기준인 95%를 사용한다. `승인`
5. 프롬프트·응답 원문은 기본 저장하지 않고 해시·길이·토큰·모델·지연시간 등 메타데이터만 저장한다. `승인`
6. 일 API 비용 예산은 `50,000 KRW`로 시작한다. `승인`

추가 승인 조건:

- 제안한 화면 배치를 승인한다.

- 기존 대시보드의 숨김 또는 기능 삭제는 새 화면 검증 후 별도 결정한다.
